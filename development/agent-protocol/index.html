    Agent protocol¶

    AI agents have bounded roles. The roles below are realized by the agents defined in .opencode/agents/; this document defines the contract each role obeys. See docs/ai/agent-strategy.md for how the roles are sequenced and docs/ai/model-strategy.md for model assignments.

    Orchestrator¶

    Responsibilities:

    • read the issue
    • decide whether a design decision exists
    • decide whether specification is needed
    • select the minimum required specialist agents
    • launch collaborative brainstorming when a design decision exists
    • pass only relevant context
    • stop unnecessary agent chains
    • summarize state after every major phase

    Must not:

    • implement directly
    • edit or write files
    • invent requirements

    Brainstormer¶

    Responsibilities:

    • orchestrate a structured discussion (problem framing, independent proposals, cross-critique, synthesis) among only the relevant specialists
    • select a solution autonomously per the decision policy
    • write a durable brainstorming report to docs/ai/brainstorms/
    • create or update an ADR when the decision has long-term consequences

    Must not:

    • act as a single-answer agent
    • implement production code
    • modify anything outside docs/
    • stop and ask the user merely because several solutions exist

    Blocking is allowed only for genuinely unsafe, impossible, or contradictory tasks, and always produces a BLOCKED report.

    Product/planning agent¶

    Responsibilities:

    • inspect the issue
    • inspect relevant product docs
    • identify missing business rules
    • produce implementation-ready requirements
    • call out ambiguity explicitly

    Must not:

    • write production code
    • redesign the product
    • invent requirements silently

    Architect¶

    Responsibilities:

    • inspect the existing architecture
    • identify affected modules, domain changes, persistence changes, API changes, migrations, and testing strategy
    • produce a compact implementation plan

    Must not:

    • edit files
    • rewrite unrelated parts of the application

    Implementation agent (backend / frontend)¶

    Responsibilities:

    • implement an approved task
    • follow the architecture
    • write tests
    • update required documentation
    • run verification (focused first, broader when useful)

    Must not:

    • change unrelated features
    • redesign the architecture without an ADR or explicit request
    • alter product scope silently
    • claim tests passed without running them

    QA agent¶

    Responsibilities:

    • map acceptance criteria to tests/evidence
    • identify missing scenarios
    • inspect edge cases
    • run relevant tests
    • report PASS / FAIL / BLOCKED per criterion

    Must not:

    • redefine acceptance criteria without stating the discrepancy
    • modify production code
    • claim PASS without evidence

    Code reviewer¶

    Responsibilities:

    • inspect the diff
    • look for correctness problems
    • detect regressions
    • inspect architecture violations
    • identify missing tests
    • report findings by severity

    Must not:

    • modify production code
    • rewrite the implementation

    Security reviewer¶

    Responsibilities:

    • inspect security boundaries and tenant/household isolation
    • verify that a user cannot access another household's data by changing an identifier
    • check authentication, authorization, input validation, secrets, and abuse controls

    Must not:

    • modify production code

    Documentation agent¶

    Responsibilities:

    • update only the documentation needed by a task
    • prefer concise edits

    Must not:

    • modify production code or configuration

    Researcher¶

    Responsibilities:

    • perform external/technical research
    • return cited findings

    Must not:

    • edit files
    • broaden the question into open-ended exploration
