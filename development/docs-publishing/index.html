    Publishing the documentation site¶

    Documentation and agent reports are rendered to a public GitHub Pages site, hosted in the dedicated public repository share-org/share-docs (https://share-org.github.io/share-docs/). The private share repository remains the single source of truth: editing docs/ there republishes the site.

    How it works¶

    The docs-publish workflow in share (.github/workflows/docs-publish.yml):

    1. Triggers on pushes to main touching docs/** or mkdocs.yml, and on manual workflow_dispatch.
    2. Builds the MkDocs Material site from docs/ (config: mkdocs.yml).
    3. Pushes the built site to the gh-pages branch of the public share-org/share-docs repository, which GitHub Pages serves.

    The GitHub Pages site in share-docs is configured to deploy from the gh-pages branch (root). GitHub Pages on the free plan requires the target repository to be public, which is why share-docs is a public repo containing only rendered static content — source code stays private.

    One-time setup¶

    1. Create a fine-grained personal access token scoped to the share-docs repository only:
    2. GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token.
    3. Repository access: Only select repositories → share-org/share-docs.
    4. Permissions: Contents → Read and write.
    5. Add it as a repository secret in share named SHARE_DOCS_TOKEN (Settings → Secrets and variables → Actions → New repository secret).

    Until the secret exists, the publish step is skipped with a warning and the site keeps its previous content.

    Triggering a republish¶

    • Automatic: any change to docs/** or mkdocs.yml on main.
    • Manual: Actions → docs-publish → Run workflow.

    Privacy note¶

    Anything under docs/ becomes world-readable once published. Keep internal notes (secrets, personal data, credentials) out of docs/.
