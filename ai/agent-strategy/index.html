    AI agent strategy¶

    Flow¶

    Human
  -> GitHub issue
  -> [brainstorming when a design decision exists]
  -> product-planner
  -> architect
  -> implementation agent (backend and/or frontend)
  -> qa-engineer
  -> code-reviewer
  -> security-reviewer (when relevant)
  -> Human review
  -> Merge

    The orchestrator decides whether brainstorming is needed before planning. See docs/ai/brainstorms/ for decision reports and the brainstorming skill.

    Default workflow (minimum set required)¶

    Issue
  -> [brainstorming when a design decision exists]
  -> product-planner
  -> architect
  -> implementation agent
  -> qa-engineer
  -> code-reviewer
  -> security-reviewer (when relevant)
  -> human review
    • Use documentation only when documentation actually changes.
    • Use researcher only for external/technical research tasks.
    • Do not fire every agent on every task. The orchestrator selects the minimum set and stops unnecessary chains.

    Orchestrator behavior¶

    • Prefer "one strong planning call + one implementation agent + one QA/review loop" over spawning many redundant agents.
    • The orchestrator never implements directly.
    • The orchestrator detects design decisions and delegates those to the brainstormer instead of deciding alone.

    Collaborative brainstorming¶

    • Runs as independent proposals -> cross-critique -> synthesis among only the relevant specialists (2-4), then selects a solution autonomously.
    • Durable report written to docs/ai/brainstorms/BR-NNN-<topic>.md; long-term decisions recorded as ADRs.
    • Agents are autonomous by default: analyze, discuss, decide, report, implement. The user receives the decision as a report and can override later.
    • Never stop simply because several solutions exist. Block only when the task is genuinely unsafe, impossible, or contradictory (BLOCKED report).

    Nesting note¶

    The standard workflow keeps subagent delegation to one level, but the brainstorming phase intentionally runs one extra level (orchestrator -> brainstormer -> specialists) as designed.

    Cheap/free model rules¶

    The system is intentionally optimized for low-cost models.

    1. Give agents one task at a time.
    2. Keep prompts short and repository rules centralized in AGENTS.md.
    3. Load documents lazily.
    4. Prefer deterministic checklists.
    5. Use specialized read-only reviewers instead of asking one model to reason about everything.
    6. Limit subagent nesting to one level.
    7. Avoid repeated whole-repository scans.
    8. Ask the model to inspect relevant files first.
    9. Use automated tests as the main correctness feedback mechanism.
    10. Make the model produce structured output.
    11. Never rely on hidden conversation memory for critical architecture decisions.
    12. Put durable knowledge into the repository.

    Agent budget policy¶

    For a small task:

    Implementation only

    For a normal feature:

    Product-planner -> Architect -> Implementer -> Reviewer

    For a high-risk feature:

    Brainstorming (when a design decision exists)
  -> Product-planner -> Architect -> Implementer -> Reviewer -> QA

    (Add security-reviewer when authentication/authorization, household data, financial logic, or external integrations are involved.)

    Do not launch all agents for every trivial change.

    Fallback policy¶

    See docs/ai/model-strategy.md. Fallbacks are optional and depend on the configured providers. After two materially similar failures, escalate or change strategy instead of blindly retrying.
