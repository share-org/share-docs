    Implementation Plan: Authentication Baseline¶

    Issue: #AUTH-001 Run: run-2026-09-29-0021 Brainstorm: none (direct planning)

    Affected areas¶

    Layer Components
    Domain New User aggregate, PasswordEncoder domain service interface
    Application RegisterUserUseCase, LoginUseCase, RefreshTokenUseCase, UserRepository port, TokenProvider port, AuthService (orchestrates)
    Infrastructure (persistence) UserJpaEntity, UserJpaRepository, UserRepositoryImpl, BCryptPasswordEncoderAdapter, JwtTokenProviderAdapter, Flyway migration V4__auth_users.sql
    Infrastructure (security) SecurityConfig, JwtAuthenticationFilter, AuthenticationEntryPoint, AccessDeniedHandler
    API AuthController with /api/auth/register, /api/auth/login, /api/auth/refresh, request/response DTOs
    Configuration application.properties additions (JWT secret, expiration), test profile updates

    Domain changes¶

    1. New User aggregate (domain/user/User.java):
    2. Fields: id (UUID), email (String, unique), passwordHash (String), createdAt (Instant)
    3. Factory method: User.register(email, rawPassword, passwordEncoder) → returns User with hashed password

    4. Method: verifyPassword(rawPassword, passwordEncoder) → boolean

    5. New PasswordEncoder interface (domain/user/PasswordEncoder.java):

    6. String encode(String rawPassword)
    7. boolean matches(String rawPassword, String encodedPassword)

    8. Pure domain interface — no Spring dependency

    9. Member remains unchanged — authentication is at User level; household membership is separate (existing Member + MemberRepository).

    Persistence / migrations¶

    Item Details
    Migration V4__auth_users.sql — new users table with id, email (unique), password_hash, created_at
    JPA Entity UserJpaEntity maps to users table
    Repository UserJpaRepository (Spring Data), UserRepositoryImpl implements UserRepository port
    No changes to existing members table — household membership stays separate
    Migration required Yes — new table, no data migration needed

    API changes¶

    Endpoint Method Request Response Auth
    /api/auth/register POST RegisterRequest(email, password) AuthResponse(accessToken, refreshToken, expiresIn) Public
    /api/auth/login POST LoginRequest(email, password) AuthResponse(accessToken, refreshToken, expiresIn) Public
    /api/auth/refresh POST RefreshRequest(refreshToken) AuthResponse(accessToken, refreshToken, expiresIn) Public (valid refresh token)
    All existing /api/** * — — Protected (JWT required)

    DTOs (in api.auth package): - RegisterRequest, LoginRequest, RefreshRequest, AuthResponse, ErrorResponse

    OpenAPI: Document all three endpoints with 200/400/401/409 responses.

    Implementation steps (ordered)¶

    1. Domain layer¶

    1.1 Create domain/user/User.java aggregate with register() factory and verifyPassword()
    1.2 Create domain/user/PasswordEncoder.java interface
    1.3 Create domain/user/UserRepository.java port interface (findByEmail, save, existsByEmail)

    2. Application layer¶

    2.1 Create application/command/auth/RegisterUserCommand.java
    2.2 Create application/command/auth/LoginCommand.java
    2.3 Create application/command/auth/RefreshTokenCommand.java
    2.4 Create application/command/auth/AuthResult.java (accessToken, refreshToken, expiresIn)
    2.4 Create application/port/TokenProvider.java port (generateAccessToken, generateRefreshToken, validateToken, extractUserId)
    2.5 Create application/usecase/auth/RegisterUserUseCase.java
    2.6 Create application/usecase/auth/LoginUseCase.java
    2.7 Create application/usecase/auth/RefreshTokenUseCase.java
    2.8 Create application/exception/auth/UserAlreadyExistsException.java, InvalidCredentialsException.java, InvalidTokenException.java

    3. Infrastructure — Persistence¶

    3.1 Create Flyway migration V4__auth_users.sql
    3.2 Create infrastructure/persistence/UserJpaEntity.java
    3.3 Create infrastructure/persistence/UserJpaRepository.java (extends JpaRepository)
    3.4 Create infrastructure/persistence/UserRepositoryImpl.java implements UserRepository
    3.5 Create infrastructure/security/BCryptPasswordEncoderAdapter.java implements PasswordEncoder (uses Spring Security's BCryptPasswordEncoder)
    3.6 Create infrastructure/security/JwtTokenProviderAdapter.java implements TokenProvider (uses io.jsonwebtoken.Jwts)

    4. Infrastructure — Security config¶

    4.1 Add dependencies to pom.xml: jjwt-api, jjwt-impl, jjwt-jackson (or use Spring Security's JWT support if preferred)
    4.2 Create infrastructure/security/SecurityConfig.java — configure SecurityFilterChain: disable CSRF, stateless session, JWT filter, permit /api/auth/**, secure /api/**
    4.3 Create infrastructure/security/JwtAuthenticationFilter.java — OncePerRequestFilter that validates JWT, sets Authentication in SecurityContext
    4.4 Create infrastructure/security/JwtAuthenticationEntryPoint.java — returns 401 for unauthenticated requests
    4.5 Create infrastructure/security/JwtAccessDeniedHandler.java — returns 403 for unauthorized access
    4.6 Create infrastructure/security/CurrentUser.java — helper to extract authenticated user ID from SecurityContext (for use in controllers/use cases)

    5. API layer¶

    5.1 Create api/auth/AuthController.java with three endpoints
    5.2 Create request/response DTOs in api.auth package
    5.3 Add @ExceptionHandler for auth exceptions returning 400/401/409
    5.4 Update OpenAPI config if needed (auto-detected via annotations)

    6. Configuration¶

    6.1 Add to application.properties: - app.jwt.secret (base64-encoded, 256+ bits) - app.jwt.access-token-expiration-minutes (e.g., 15) - app.jwt.refresh-token-expiration-days (e.g., 30) 6.2 Update application-test.properties: keep spring.security.enabled=false for non-auth tests, add @AutoConfigureMockMvc + @SpringBootTest for auth tests with security enabled

    7. Integration wiring¶

    7.1 Ensure UserRepositoryImpl, BCryptPasswordEncoderAdapter, JwtTokenProviderAdapter are @Component / @Repository / @Service
    7.2 Wire use cases in Spring context (constructor injection)

    Open questions¶

    1. Token storage: Refresh tokens — store hash in DB (revocable) or stateless JWT with short expiry + refresh token rotation? Stateless is simpler for MVP; revocable adds a refresh_tokens table. Recommendation: Start stateless with rotation (issue new refresh token on each refresh, invalidate old).

    2. Email uniqueness: Global (across all households) or per-household? Current members table has UNIQUE (household_id, email). For users table, global unique email makes sense for login.

    3. User ↔ Member linking: When a registered user creates/joins a household, how to link? Option A: User has memberId per household (many-to-many via join table). Option B: Keep separate — Member has optional userId FK. Recommendation: Option B — add nullable user_id to members table in a future migration (not in Phase 0).

    4. Password requirements: Min length, complexity? Enforce at API layer (validation annotations) and/or domain.

    5. Rate limiting: Apply to /api/auth/* endpoints? Defer to follow-up (per security.md abuse considerations).

    6. JWT library: io.jsonwebtoken:jjwt (0.12.x) vs Spring Security's built-in JwtDecoder/JwtEncoder (Spring Security 6+). Recommendation: Use jjwt for token generation/parsing (more control), Spring Security for filter chain integration.

    7. Test profile security: Current tests disable security globally (spring.security.enabled=false). For auth tests, need a separate test slice or profile with security enabled. Approach: Create AuthControllerTest with @ActiveProfiles("auth-test") and separate application-auth-test.properties with security enabled.

    This plan follows the existing hexagonal architecture: domain has no Spring deps, application uses ports, infrastructure provides adapters, controllers are thin. All new code fits the modular monolith structure.
