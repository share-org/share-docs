    PLAN 36 opencode rate limit fix

    Affected areas¶

    • .github/actions/opencode-install/action.yml (NEW - composite action)
    • .github/workflows/project-manager-loop.yml
    • .github/workflows/opencode-pr-review.yml
    • .github/workflows/opencode-command.yml
    • .github/workflows/opencode-pipeline.yml
    • .github/workflows/opencode-prototype-feedback.yml
    • .github/workflows/opencode-issue-triage.yml
    • .github/workflows/opencode-agent-status.yml

    Domain changes¶

    None. This is an infrastructure/CI fix only.

    Persistence / migrations¶

    None.

    API changes¶

    None. The composite action preserves the exact same input interface as the upstream action: - agent (required) - model (required) - prompt (required) - use_github_token (optional, boolean) - Any other inputs the upstream action accepts

    Ordered implementation steps¶

    Step 1: Investigate opencode distribution¶

    • Check https://github.com/anomalyco/opencode/releases for release artifacts
    • Examine the upstream action source (if public) to understand installation method
    • Determine: binary tarball? npm package? install script? Docker image?
    • Identify current stable version to pin

    Step 2: Create local composite action¶

    Create .github/actions/opencode-install/action.yml with: - Inputs mirroring upstream: agent, model, prompt, use_github_token, plus any others discovered - Pinned opencode version (e.g., OPENCODE_VERSION: "v0.1.23") - Installation logic using authenticated GitHub API (if downloading from releases) or direct method (npm, script) - Execution logic that invokes opencode with the provided inputs - Robust error handling and logging - Uses GITHUB_TOKEN from env for authenticated API calls

    Step 3: Test with one workflow¶

    • Modify opencode-pr-review.yml to use uses: ./.github/actions/opencode-install
    • Run a test PR to verify the action works end-to-end
    • Verify agent runs successfully, posts review comment

    Step 4: Migrate remaining 6 workflows¶

    Update uses: in each workflow: 1. project-manager-loop.yml line 189 2. opencode-command.yml lines 160, 214, 286 (3 jobs) 3. opencode-pipeline.yml line 168 4. opencode-prototype-feedback.yml line 175 5. opencode-issue-triage.yml line 70 6. opencode-agent-status.yml line 47

    Step 5: Verify all workflows¶

    • Trigger each workflow (or wait for natural triggers)
    • Confirm all agent jobs start and complete without rate limit errors
    • Check that identity markers, status comments, and labels work correctly

    Step 6: Document version update process¶

    • Add note in docs/development/ or action README about how to update opencode version
    • Consider adding a Dependabot-like check or manual process

    Tests¶

    • Integration test: Each workflow runs successfully on GitHub Actions
    • Manual verification: Create a test PR, verify opencode-pr-review posts a review
    • Manual verification: Trigger /oc manager run, verify project-manager cycle completes
    • Manual verification: Create an issue, verify opencode-issue-triage runs
    • Regression test: Ensure no workflow fails with "Get opencode version" step

    Risks¶

    1. Upstream distribution change: If opencode changes how it's distributed, our action breaks
    2. Mitigation: Pin version; monitor upstream releases; test in branch before merge
    3. Missing inputs: If upstream action has undocumented inputs, our mirror may be incomplete
    4. Mitigation: Check all 7 workflows for any input variations; mirror all
    5. Version pin drift: Forgetting to update version when needed
    6. Mitigation: Document update process; consider scheduled check
    7. Authentication scope: GITHUB_TOKEN may lack contents:read in some workflows
    8. Mitigation: All affected workflows already have contents: read or write permissions

    Open questions¶

    1. What is the exact opencode installation method? (binary, npm, script, Docker?)
    2. What is the current stable version to pin?
    3. Does the upstream action do any setup beyond installation (auth config, environment variables)?
    4. Are there any action inputs used in workflows that aren't in the standard set?
