    Task Breakdown: AUTH-001 Authentication Baseline¶

    Parent Plan: PLAN-AUTH-001-authentication-baseline.md
    Issue: #AUTH-001
    Run: run-2026-09-29-XXXX

    Overview¶

    The authentication baseline is decomposed into 4 independently implementable tasks, ordered by architectural layer (domain → application → infrastructure → API). Each task has: - Clear scope and deliverables - Explicit dependencies on prior tasks - Acceptance criteria verifiable by tests - Estimated complexity

    Task 1: Domain Layer — User Aggregate & Ports¶

    Label: task:auth-domain
    Depends on: None (foundation task)
    Complexity: Low

    Scope¶

    Create the pure domain layer for authentication — no Spring dependencies.

    Deliverables¶

    File Purpose
    domain/user/User.java Aggregate root with register() factory, verifyPassword(), fields: id (UUID), email, passwordHash, createdAt
    domain/user/PasswordEncoder.java Domain interface: encode(), matches()
    domain/user/UserRepository.java Port interface: findByEmail(), save(), existsByEmail()

    Acceptance Criteria¶

    • [ ] User.register(email, rawPassword, encoder) returns User with hashed password
    • [ ] User.verifyPassword(rawPassword, encoder) returns true for correct password, false otherwise
    • [ ] PasswordEncoder interface compiles with no Spring imports
    • [ ] Unit tests cover: registration hashing, password verification (correct/incorrect), email uniqueness invariant
    • [ ] Domain layer has zero dependencies on Spring, JPA, or infrastructure

    Test File¶

    • domain/user/UserTest.java

    Task 2: Application Layer — Use Cases, Commands & Ports¶

    Label: task:auth-application
    Depends on: Task 1 (domain ports)
    Complexity: Medium

    Scope¶

    Implement application use cases orchestrating the domain, using ports for infrastructure.

    Deliverables¶

    File Purpose
    application/command/auth/RegisterUserCommand.java Input: email, password
    application/command/auth/LoginCommand.java Input: email, password
    application/command/auth/RefreshTokenCommand.java Input: refreshToken
    application/command/auth/AuthResult.java Output: accessToken, refreshToken, expiresIn
    application/port/TokenProvider.java Port: generateAccessToken(), generateRefreshToken(), validateToken(), extractUserId()
    application/usecase/auth/RegisterUserUseCase.java Validates uniqueness, creates User, returns tokens
    application/usecase/auth/LoginUseCase.java Verifies credentials, returns tokens
    application/usecase/auth/RefreshTokenUseCase.java Validates refresh token, issues new token pair
    application/exception/auth/UserAlreadyExistsException.java 409 Conflict
    application/exception/auth/InvalidCredentialsException.java 401 Unauthorized
    application/exception/auth/InvalidTokenException.java 401 Unauthorized

    Acceptance Criteria¶

    • [ ] RegisterUserUseCase rejects duplicate email → UserAlreadyExistsException
    • [ ] LoginUseCase rejects invalid email/password → InvalidCredentialsException
    • [ ] RefreshTokenUseCase rejects expired/invalid refresh token → InvalidTokenException
    • [ ] All use cases accept commands, return AuthResult, delegate to ports
    • [ ] Unit tests with mocked ports cover: happy paths, duplicate email, invalid credentials, expired/invalid refresh token
    • [ ] No Spring annotations in application layer (pure Java)

    Test Files¶

    • application/usecase/auth/RegisterUserUseCaseTest.java
    • application/usecase/auth/LoginUseCaseTest.java
    • application/usecase/auth/RefreshTokenUseCaseTest.java

    Task 3: Infrastructure — Persistence Adapters & Security Adapters¶

    Label: task:auth-infrastructure-adapters
    Depends on: Task 1 (domain ports), Task 2 (application ports)
    Complexity: Medium-High

    Scope¶

    Implement JPA persistence for User, BCrypt password encoding, and JWT token provider. Add Flyway migration.

    Deliverables¶

    File Purpose
    db/migration/V4__auth_users.sql Creates users table: id (UUID PK), email (unique), password_hash, created_at
    infrastructure/persistence/UserJpaEntity.java JPA entity mapping to users table
    infrastructure/persistence/UserJpaRepository.java Spring Data JpaRepository<UserJpaEntity, UUID>
    infrastructure/persistence/UserRepositoryImpl.java Implements UserRepository port using JPA repository
    infrastructure/security/BCryptPasswordEncoderAdapter.java Implements PasswordEncoder using Spring Security's BCryptPasswordEncoder
    infrastructure/security/JwtTokenProviderAdapter.java Implements TokenProvider using io.jsonwebtoken.Jwts (stateless, rotation)

    Acceptance Criteria¶

    • [ ] Migration V4__auth_users.sql runs cleanly on empty PostgreSQL (Testcontainers)
    • [ ] UserRepositoryImpl implements all port methods correctly (findByEmail, save, existsByEmail)
    • [ ] BCryptPasswordEncoderAdapter encodes/verifies passwords per BCrypt standard
    • [ ] JwtTokenProviderAdapter:
    • Generates access token (15 min expiry) and refresh token (30 day expiry)
    • Validates token signature and expiry
    • Extracts user ID from token
    • Implements refresh token rotation (new refresh token issued on each refresh)
    • [ ] Integration tests with Testcontainers verify: save/find user, password encoding, token generation/validation/refresh
    • [ ] All adapters are Spring components (@Repository, @Component, @Service)

    Test Files¶

    • infrastructure/persistence/UserRepositoryImplTest.java (Testcontainers)
    • infrastructure/security/BCryptPasswordEncoderAdapterTest.java
    • infrastructure/security/JwtTokenProviderAdapterTest.java

    Configuration¶

    • Add to pom.xml: io.jsonwebtoken:jjwt-api, jjwt-impl, jjwt-jackson (0.12.x)

    Task 4: Infrastructure — Security Config & API Layer¶

    Label: task:auth-security-api
    Depends on: Task 3 (adapters must exist for wiring)
    Complexity: Medium-High

    Scope¶

    Wire Spring Security filter chain, JWT authentication filter, exception handlers, and REST endpoints.

    Deliverables¶

    File Purpose
    infrastructure/security/SecurityConfig.java SecurityFilterChain: disable CSRF, stateless, JWT filter, permit /api/auth/**, secure /api/**
    infrastructure/security/JwtAuthenticationFilter.java OncePerRequestFilter: validates JWT, sets Authentication in SecurityContext
    infrastructure/security/JwtAuthenticationEntryPoint.java Returns 401 JSON for unauthenticated requests
    infrastructure/security/JwtAccessDeniedHandler.java Returns 403 JSON for unauthorized access
    infrastructure/security/CurrentUser.java Helper to extract authenticated user ID from SecurityContext
    api/auth/AuthController.java REST endpoints: POST /api/auth/register, POST /api/auth/login, POST /api/auth/refresh
    api/auth/dto/RegisterRequest.java @Valid email, password
    api/auth/dto/LoginRequest.java @Valid email, password
    api/auth/dto/RefreshRequest.java @Valid refreshToken
    api/auth/dto/AuthResponse.java accessToken, refreshToken, expiresIn
    api/auth/dto/ErrorResponse.java Standard error format
    api/auth/AuthControllerAdvice.java @ExceptionHandler mapping domain exceptions to 400/401/409

    Configuration Updates¶

    • application.properties: app.jwt.secret, app.jwt.access-token-expiration-minutes, app.jwt.refresh-token-expiration-days
    • application-test.properties: separate profile for auth tests with security enabled

    Acceptance Criteria¶

    • [ ] POST /api/auth/register → 201 + AuthResponse on success, 409 on duplicate email
    • [ ] POST /api/auth/login → 200 + AuthResponse on success, 401 on invalid credentials
    • [ ] POST /api/auth/refresh → 200 + new AuthResponse (rotated refresh token), 401 on invalid/expired refresh token
    • [ ] All /api/** endpoints (except /api/auth/**) return 401 without valid JWT
    • [ ] JWT filter extracts user ID and populates SecurityContext for downstream use
    • [ ] OpenAPI/Swagger documents all 3 endpoints with 200/400/401/409 responses
    • [ ] API tests with MockMvc + security enabled cover all endpoints and error cases
    • [ ] Existing protected endpoint tests updated to include JWT authorization

    Test Files¶

    • api/auth/AuthControllerTest.java (@SpringBootTest + MockMvc, security enabled)
    • Update HouseholdControllerTest.java (or equivalent) to inject JWT in requests

    Dependency Graph¶

    Task 1 (Domain)
    ↓
Task 2 (Application) ──────┐
    ↓                       │
Task 3 (Adapters) ◄─────────┘ (implements ports from Task 1 & 2)
    ↓
Task 4 (Security + API)    (wires adapters from Task 3)

    Execution Notes¶

    For Delegation¶

    • Each task can be assigned to a separate backend-implementer invocation
    • Tasks 1 & 2 are pure Java — no Spring context needed for unit tests
    • Task 3 requires Testcontainers (PostgreSQL) for integration tests
    • Task 4 requires full Spring Boot context (@SpringBootTest)

    Recommended Order¶

    1. Task 1 → Task 2 → Task 3 → Task 4 (sequential, each unlocks the next)
    2. Tasks 1 & 2 can run in parallel if two agents available (both depend only on domain)
    3. Task 3 and 4 must be sequential (Task 4 wires Task 3's beans)

    Verification Gates¶

    After each task, run its dedicated tests:

    # Task 1
./mvnw test -Dtest=UserTest

# Task 2
./mvnw test -Dtest=*UseCaseTest

# Task 3
./mvnw test -Dtest=UserRepositoryImplTest,BCryptPasswordEncoderAdapterTest,JwtTokenProviderAdapterTest

# Task 4
./mvnw test -Dtest=AuthControllerTest

    Out of Scope (Deferred)¶

    • Refresh token persistence/revocation (stateless rotation chosen for MVP)
    • User ↔ Member linking (future migration)
    • Rate limiting on auth endpoints
    • Password complexity rules (basic @Size validation only)
    • Email verification flow
