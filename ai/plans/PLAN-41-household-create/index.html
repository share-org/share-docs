    Implementation Specification: HOUSE-001 Create Household¶

    Overview¶

    This specification covers the implementation of household creation (POST /api/households), the first capability in Phase 1 of the roadmap. The creator becomes the first member with OWNER role. Household isolation is enforced at all layers.

    2.3 Use Case¶

    package com.sharedhousehold.application.usecase.household;

import com.sharedhousehold.application.command.household.CreateHouseholdCommand;
import com.sharedhousehold.application.command.household.CreateHouseholdResult;
import com.sharedhousehold.application.exception.InvalidHouseholdException;
import com.sharedhousehold.application.port.household.HouseholdRepository;
import com.sharedhousehold.application.port.MemberRepository;
import com.sharedhousehold.domain.household.Household;
import com.sharedhousehold.domain.household.HouseholdId;
import com.sharedhousehold.domain.household.HouseholdMember;
import com.sharedhousehold.domain.household.MemberRole;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.context.ApplicationEventPublisher;

import java.time.Instant;
import java.util.UUID;

@Service
@Transactional
public class CreateHouseholdUseCase {

    private final HouseholdRepository householdRepository;
    private final MemberRepository memberRepository;
    private final ApplicationEventPublisher eventPublisher;

    public CreateHouseholdUseCase(HouseholdRepository householdRepository,
                                   MemberRepository memberRepository,
                                   ApplicationEventPublisher eventPublisher) {
        this.householdRepository = householdRepository;
        this.memberRepository = memberRepository;
        this.eventPublisher = eventPublisher;
    }

    public CreateHouseholdResult execute(CreateHouseholdCommand command) {
        // 1. Validate creator email uniqueness within household (not needed for new household, but keep for consistency)
        // 2. Create Household aggregate
        HouseholdId householdId = HouseholdId.generate();
        Household household = Household.create(householdId, command.name());

        // 3. Create creator as OWNER member
        UUID creatorMemberId = UUID.randomUUID();
        HouseholdMember ownerMember = HouseholdMember.createOwner(creatorMemberId, householdId);

        // 4. Persist household first
        Household savedHousehold = householdRepository.save(household);

        // 5. Persist creator member
        Member creatorMember = new Member(creatorMemberId, householdId.getValue(), command.creatorName(), command.creatorEmail());
        Member savedMember = memberRepository.save(creatorMember);

        // 6. Publish domain events
        eventPublisher.publishEvent(new HouseholdCreated(householdId, command.name(), creatorMemberId, Instant.now()));
        eventPublisher.publishEvent(new MemberAdded(householdId, creatorMemberId, MemberRole.OWNER, Instant.now()));

        return new CreateHouseholdResult(
                savedHousehold.getId(),
                savedHousehold.getName(),
                savedMember.id(),
                MemberRole.OWNER,
                savedHousehold.getCreatedAt());
    }
}

    3.1 Flyway Migration: V3__household_and_members.sql¶

    -- V3__household_and_members.sql
-- The households table already exists from V1. Members table also exists.
-- We need to add role column to members and ensure household creation works.

-- Add role column to members table
ALTER TABLE members
    ADD COLUMN role VARCHAR(20) NOT NULL DEFAULT 'MEMBER';

-- Add index for role queries
CREATE INDEX idx_members_household_id_role ON members (household_id, role);

-- Update existing members to have MEMBER role (data migration)
UPDATE members SET role = 'MEMBER' WHERE role IS NULL;

    Note: The households and members tables are already created in V1__initial_schema.sql. This migration only adds the role column.

    3.4 Repository Adapter Implementation¶

    HouseholdRepositoryImpl¶

    package com.sharedhousehold.infrastructure.persistence.household;

import com.sharedhousehold.application.port.household.HouseholdRepository;
import com.sharedhousehold.domain.household.Household;
import com.sharedhousehold.domain.household.HouseholdId;
import java.util.Optional;
import java.util.UUID;
import org.springframework.stereotype.Repository;

@Repository
public class HouseholdRepositoryImpl implements HouseholdRepository {

    private final HouseholdJpaRepository householdJpaRepository;
    private final HouseholdMapper mapper;

    public HouseholdRepositoryImpl(HouseholdJpaRepository householdJpaRepository, HouseholdMapper mapper) {
        this.householdJpaRepository = householdJpaRepository;
        this.mapper = mapper;
    }

    @Override
    public Household save(Household household) {
        HouseholdJpaEntity entity = HouseholdMapper.toJpaEntity(household);
        HouseholdJpaEntity savedEntity = householdJpaRepository.save(entity);
        return HouseholdMapper.toDomain(savedEntity);
    }

    @Override
    public Optional<Household> findById(HouseholdId id) {
        return householdJpaRepository.findById(id.getValue())
                .map(HouseholdMapper::toDomain);
    }

    @Override
    public boolean existsById(HouseholdId id) {
        return householdJpaRepository.existsById(id.getValue());
    }
}

    HouseholdMapper¶

    package com.sharedhousehold.infrastructure.persistence.household;

import com.sharedhousehold.domain.household.Household;
import com.sharedhousehold.domain.household.HouseholdId;
import java.time.Instant;
import java.util.UUID;
import org.springframework.stereotype.Component;

@Component
public final class HouseholdMapper {

    private HouseholdMapper() {}

    public static HouseholdJpaEntity toJpaEntity(Household household) {
        return new HouseholdJpaEntity(
                household.getId().getValue(),
                household.getName(),
                household.getCreatedAt(),
                household.getUpdatedAt());
    }

    public static Household toDomain(HouseholdJpaEntity entity) {
        return Household.reconstruct(
                HouseholdId.of(entity.getId()),
                entity.getName(),
                entity.getCreatedAt(),
                entity.getUpdatedAt());
    }
}

    4.3 Controller¶

    package com.sharedhousehold.api.household;

import com.sharedhousehold.application.command.household.CreateHouseholdCommand;
import com.sharedhousehold.application.command.household.CreateHouseholdResult;
import com.sharedhousehold.application.exception.household.InvalidHouseholdException;
import com.sharedhousehold.application.usecase.household.CreateHouseholdUseCase;
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.media.Content;
import io.swagger.v3.oas.annotations.media.Schema;
import io.swagger.v3.oas.annotations.responses.ApiResponse;
import io.swagger.v3.oas.annotations.responses.ApiResponses;
import io.swagger.v3.oas.annotations.tags.Tag;
import jakarta.validation.Valid;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/households")
@Tag(name = "Households", description = "Household management endpoints")
public class HouseholdController {

    private final CreateHouseholdUseCase createHouseholdUseCase;

    public HouseholdController(CreateHouseholdUseCase createHouseholdUseCase) {
        this.createHouseholdUseCase = createHouseholdUseCase;
    }

    @PostMapping
    @Operation(
            summary = "Create a new household",
            description = "Creates a new household with the requester as the owner member")
    @ApiResponses(value = {
            @ApiResponse(
                    responseCode = "201",
                    description = "Household created successfully",
                    content = @Content(schema = @Schema(implementation = CreateHouseholdResponse.class))),
            @ApiResponse(
                    responseCode = "400",
                    description = "Invalid request data",
                    content = @Content(schema = @Schema(implementation = ErrorResponse.class))),
            @ApiResponse(
                    responseCode = "409",
                    description = "Email already in use (future: when auth is added)",
                    content = @Content(schema = @Schema(implementation = ErrorResponse.class)))
    })
    public ResponseEntity<CreateHouseholdResponse> createHousehold(@Valid @RequestBody CreateHouseholdRequest request) {
        CreateHouseholdCommand command = new CreateHouseholdCommand(
                request.name(),
                request.creatorName(),
                request.creatorEmail());

        CreateHouseholdResult result = createHouseholdUseCase.execute(command);
        return ResponseEntity.status(HttpStatus.CREATED).body(toResponse(result));
    }

    @ExceptionHandler(InvalidHouseholdException.class)
    public ResponseEntity<ErrorResponse> handleInvalidHousehold(InvalidHouseholdException e) {
        return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(new ErrorResponse(e.getMessage()));
    }

    @ExceptionHandler(IllegalArgumentException.class)
    public ResponseEntity<ErrorResponse> handleIllegalArgument(IllegalArgumentException e) {
        return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(new ErrorResponse(e.getMessage()));
    }

    private CreateHouseholdResponse toResponse(CreateHouseholdResult result) {
        return new CreateHouseholdResponse(
                result.householdId().getValue(),
                result.name(),
                result.creatorMemberId(),
                result.creatorRole().name(),
                result.createdAt());
    }

    @Schema(description = "Error response")
    public record ErrorResponse(@Schema(description = "Error message") String message) {}
}

    5. Security: Household Isolation¶

    5.1 Current State¶

    No authentication/authorization framework is configured yet (tests exclude SecurityAutoConfiguration). Household isolation for this endpoint is enforced by: - Household ID is generated server-side (not from client request body) - Creator member ID is generated server-side - No household ID in request path or body for creation

    5.2 Future-Proofing¶

    When authentication is added (Phase 1: Authentication), the controller will: - Extract authenticated user identity from security context - Use authenticated user's ID instead of generating a new member ID - Validate email ownership

    For now, the endpoint is open but creates isolated households by design.

    5.3 Isolation Enforcement Points¶

    1. Domain: Household aggregate only exposes its own HouseholdId
    2. Application: HouseholdRepository.findById takes HouseholdId (not raw UUID)
    3. Infrastructure: JPA queries always filter by household_id
    4. API: No household ID in create request; subsequent endpoints use path variable {householdId}

    • Email uniqueness validation across households (requires auth)
    • Audit logging beyond createdAt/updatedAt (future)
    • Domain event outbox pattern (direct publication is sufficient for MVP)

    10. Open Questions¶

    1. Email uniqueness: Should we enforce unique email per household at DB level? (Current V1 schema has UNIQUE (household_id, email) — this is correct for within-household uniqueness. Cross-household uniqueness requires auth.)

    2. Member ID generation: Should the creator's member ID be deterministic (e.g., derived from email) or random UUID? Random UUID is simpler and matches existing pattern.

    3. Household name uniqueness: Should household names be unique globally? No — different households can have same name.

    4. Event publication: Use Spring's ApplicationEventPublisher (synchronous) or async? Synchronous is fine for MVP; async can be added later.

    5. Creator email validation: Should we validate email format in domain or only in API? API validation (Jakarta @Email) is sufficient; domain doesn't need to know email format rules.
