    Runs¶

    Durable per-run records for the GitHub-native agent workflow.

    Run ID format¶

    Every automated execution gets a unique run ID:

    run-YYYY-MM-DD-NNNN

    NNNN is the per-workflow GitHub Actions run number, padded. See scripts/oc-run-id.sh for the generator used by the workflows.

    Where run IDs appear¶

    • GitHub status comments on Issues/PRs (Run: \run-...``)
    • PR descriptions (AI Execution table)
    • Git trailers on agent commits (Agent-Run: run-...)
    • brainstorm reports and decision reports (front-matter/header)
    • workflow logs and the Actions run URL

    Persisting a run report¶

    Keep the repository lean. Persist a file here only when useful, for example to record blocking conditions, unusual decisions, or a post-mortem of a failed end-to-end run. Naming convention:

    run-2026-09-22-0017.md

    Suggested structure:

    # Run run-2026-09-22-0017

Issue: #N
Agent: <name>
Model: <provider/model>
Trigger: <event or /oc command>
Result: <PASS / FAIL / BLOCKED>
Workflow: <link to GitHub Actions run>
Links: <branch, PR, brainstorm, ADR>
Notes: <what happened, why it matters, follow-ups>

    For routine runs, the GitHub Issue/PR thread plus workflow logs are the record; do not duplicate them here.
